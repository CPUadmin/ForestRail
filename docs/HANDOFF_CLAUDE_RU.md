## Что сделано (всё в этой ветке)

- **N1 экономика 3.2:** ручная → паровоз 500 → бензиновая 1000 → электровоз 3000; у трёх последних 0 мест на кузове, груз только в вагонах; платное пополнение; ручная сцепка в депо.
- **N6 электровоз:** кривая тяги по заряду, полоска заряда на корпусе; пульт — только тяга и тормоз, без коробки, пуска и холостого расхода.
- **N7.1 карта и HUD:** профиль пути на карте M, миникарта, нижняя полоса ~11%. N7.2–N7.3 не начаты.
- **N4 паровоз:** топка (уголь из ведра перетаскивается мышью при открытой дверце), отдельный розжиг щелчком, кран воды, давление 0–10 бар (рабочее с 3), прогрев ~25–30 с, пружинный вентиль 2.5 с (не тормозит), предохранительный клапан, огонь гаснет без угля, пара нет без огня и воды. Параметры — блок `boiler` в `game_data.json`. Котёл хранится в `fleet_by_id.steam`; в депо огонь гасится, уголь в топке остаётся. Вентиль и кран воды — **колёса**, которые крутят по кругу (0–270°), вентиль с пружиной, кран держит положение.
- **N5 бензиновая:** передачи R/N/1–4, обороты 800–6000, удушье высоких передач на малом ходу, обрыв тяги при переключении на ходу, задняя только на остановке, расход зависит от оборотов. Передача выбирается шаром по **H-кулисе** (нейтральный канал, колонки 1/2, 3/4, R внизу справа). Старые сохранения: Н/1/2 → N/1/4 (`state.gearbox = 4`).
- **Облик:** паровоз и бензиновая нарисованы кодом (`tools/make_steam_art.py`, `make_petrol_art.py`, колёса `make_steam_wheel.py`, `make_petrol_wheel.py`). Исходные листы-референсы владельца — `tools/art_sources/` (вдохновение, в игру не копировать; часть деталей паровоза вырезана из `steam_sheet_v2.webp`). Живые детали (огонь, стрелка манометра, дым, свет фары, шатуны, ползун) рисуются в `art_v3.gd`.
- **Платформы по классам:** ручная 2.4 м, паровоз 3.0, бензиновая 3.6, электровоз 4.0 (вагон 2.8). Скрипты картинок имеют таблицу `XMAP` (растягивает участки рисунка до нужной длины, круглые детали остаются круглыми). Колёса: паровоз ±0.8 м, бензиновая ±1.1 м.
- **Управление в кабине:** снаружи на машине только тормоз и тяга (новая функция `draw_lever`, `world_control_ids()`); остальное (кулиса, кран, розжиг, дверца, уголь) — только в пульте по `C` (`control_ids()`). Вид органа задаёт `control_kind()`: lever / wheel / gate / toggle.
- **HUD:** цветной спидометр (латунный ободок, зоны зелёная/жёлтая/красная), панели с цветными акцентами, полосы уровня и уклон окрашены.
- **Плавность:** модель шагает 60 Гц, рисунок — с частотой экрана. Позиции для отрисовки берутся через `model.body_s_render()` / `render_s()` (сдвиг на недоделанную часть шага `Engine.get_physics_interpolation_fraction()` × `last_movement`); физика и тесты используют обычные `body_s()`. Не заменяй обратно. HUD перерисовывается 30 раз в секунду. Замер кадра — тест `check_perf` (время кадра по машинам с HUD и без); абсолютные FPS на этом ПК зависят от нагрузки, сравнивай со старым коммитом в `git worktree` и запускай его собственный `tools/run_checks.py`.
- **Баг камеры:** камера теперь следует за поездом, пока держишь рычаг (раньше замораживалась, и поезд «уезжал»). Это отступление от ТЗ 7.2 («фиксируется при захвате»): ввод считается в системе координат машины, замораживать камеру больше не нужно.

## Как проверять

- Тесты: `python tools/run_checks.py <godot.exe> --manual-run --report-dir <папка вне репо> --suite <список>`. Наборы: check_model, check_physics, drive_campaign, check_handcar_revision, check_art_v3, check_mechanism, check_handcar_drive, check_interaction, check_instruments, check_presentation, check_station_service, check_world_geometry, check_mechanism_bench, check_handcar_input, check_motor_controls, check_loading_selection, check_layout_p7, **check_steam, check_gearbox, check_steam_view, check_petrol_view** (последние два делают скриншоты в `<report-dir>/steam_view` и `petrol_view`). `check_save_p8` без `--migration-save=` выходит с кодом 2.
- **Оконные наборы** (interaction, instruments, station_service, world_geometry, loading_selection, layout_p7 и др.) кликают по реальному окну: если пользователь работает за компьютером, они иногда падают (фокус). Падает случайно — прогоняй этот набор отдельно ещё раз. Не правь файлы проекта, пока идёт прогон.
- Новый тестовый набор: файл `tests/<имя>.gd`, имя добавить в список в `scripts/main.gd` (`--qa-suite`) и в словарь `marker` в `tools/run_checks.py`.
- После правок ассетов: `godot --headless --path ForestRail --import`. Скриншоты: 1600×900 и 1280×720.
- Тесты покупают технику через `tests/fixtures.gd` (`equip`, `fire_up` для паровоза).

## Выпуск и ярлык

1. Подними `config/version` в `ForestRail/project.godot` (сейчас `1.2.0-preview.13`).
2. `godot --headless --path ForestRail --import`, затем `--export-release "Windows Desktop" <путь>\ForestRail.exe` (один exe, pck встроен, шаблон `tools/templates/windows_release_x86_64.exe`). Экспорт кладите во временную папку, не в `release/` (она в `.gitignore`).
3. Проверь собранный exe: `run_checks.py <exe> --exported --suite check_model,check_gearbox,check_steam`.
4. Скопируй exe в `%LOCALAPPDATA%\Programs\ForestRail\<версия>\ForestRail.exe` (старые версии не удалять) и перенаправь ярлык «Лесная колея» на рабочем столе (поиск `.lnk` по цели `Programs\ForestRail\*ForestRail.exe`, PowerShell `WScript.Shell`).
5. Сохранения в `%APPDATA%\ForestRail`; новая версия должна читать старые.

## Правила работы

- Один этап — один небольшой коммит с исходниками, данными, проверкой и честным статусом в `docs/AI_IMPLEMENTATION_STAGES_v3.md`. Не выдавай непроверенное за проверенное: автотесты и проба человеком — разные вещи.
- Не коммить чужие незавершённые папки (`outputs/`, `work/`) и отчёты `qa/`. В конце коммита сообщение должно содержать строку `Co-Authored-By: ...`, если её требует окружение.
- Числа в UI бери из данных, не хардкодь. Не исправляй тесты под неправильное поведение.
- Крупные решения по геймплею и экономике сначала предлагай. Вопросы владельцу короткие, по делу.
- Не пушить и не публиковать без просьбы владельца; пуш ветки `claude/visual-v3` владелец разрешил при просьбе «запиши в гитхабе».
