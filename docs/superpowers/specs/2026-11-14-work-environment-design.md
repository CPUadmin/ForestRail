# Рабочая среда «Лесной колеи» (дизайн, 14.11.2026)

## Зачем

Владелец решил: сделать рабочую среду **ближайшим приоритетом**. Работают двое: владелец и Claude (плюс GPT рисует картинки), только на этом компьютере. GitHub служит хранилищем. Цель: владелец за минуту находит, что ему нужно, а новый чат Claude сразу знает правила проекта и инструменты и ничего не теряет между сессиями.

## Цели

1. **`CLAUDE.md` в корне:** правила проекта для Claude (путь к Godot, как гонять тесты и только по одному, выпуск только по слову владельца, «никогда git add -A», картинки через GPT, первое правило про навыки и смену модели, ссылки на план).
2. **Инструменты в проекте, а не во временной папке:** `tools/run_all_checks.py` (все наборы по одному, итог одной таблицей), `tools/visual_audit.py` (снимки и лист для глаз), `tools/release.py` (сборка по шагам из «Ворот качества», каждый шаг печатает, что сделал). Путь к Godot хранится в одном месте: `tools/local_settings.json` (не в git), с понятной ошибкой, если файла нет.
3. **Кнопки для владельца** (двойной клик, в корне папка `КНОПКИ/`): «Проверить всё», «Собрать пробную версию», «Открыть картинки GPT», «Открыть план». Каждая пишет по-русски, что делает и чем кончилось.
4. **`README_RU.md` заново, коротко:** что за игра, что сейчас, как запустить, где план, где кнопки. Старый текст уходит в архив.
5. **`docs/` с оглавлением:** `docs/README_RU.md` объясняет, что читать (план, простой план, предложения, правила). Старые отчёты и версии планов переезжают в `docs/archive/`, ссылки на них поправлены.
6. **Чистый `git status`** (решения судьи, ничего не удаляется):
   - входящие пакеты GPT (П13, П17, П18 папкой, П19, П20, два концепта) и отчёты приёмки **добавить в git**, как все прошлые пакеты; архив `P18_ui_kit.zip` повторяет папку, поэтому в `.gitignore`;
   - 28 файлов `.uid` от Godot **добавить в git** (Godot советует их хранить);
   - старые неиспользуемые картинки `jet_train_*` и `rail_zeppelin_*` (кроме живой `rail_zeppelin_compact_body`) **переносятся** из игры в `tools/art_sources/archive/unused_consists/` и добавляются в git;
   - `qa/visual_audit_1104/`, `qa/autonomous_run_1105/`, `qa/night_report_2026-11-05/` **в `.gitignore`** (старые снимки, остаются на диске);
   - `qa/perf_baseline.json` **в git** (база замера скорости этой машины);
   - `outputs/` (1,9 ГБ), `work/`, `release/` и `qa_import.log` уже исключены, остаются на диске.
7. **Потерянные идеи** из старых документов собрать в план (раздел «Парковка»), правила свести в `CLAUDE.md` и `docs/RULES_RU.md`.

## Не делаем

- Автопроверку на GitHub (решение владельца).
- Удаление файлов с диска. Только перенос и `.gitignore`.
- Правки кода игры, версии, тегов и выпусков.

## Подходы (выбрано А)

- **А. Порядок и инструменты внутри проекта:** всё выше. **Выбрано владельцем.**
- Б. Минимум (`CLAUDE.md`, README, перенос скриптов): быстрее, но бардак в `docs/` и в git остаётся.
- В. А плюс автопроверка на GitHub: лишнее, Godot для тестов стоит локально.

## Решения, которые принял Claude (можно поправить)

- Кнопки лежат в `КНОПКИ/` в корне (по-русски, чтобы видно сразу), это `.bat`, которые зовут Python-скрипты.
- `release.py` в этом шаге не выпускает сам: только собирает пробную сборку и проверяет её. Тег, GitHub и ярлык остаются за словом владельца, как и раньше.
- Правило выпусков владельца от 14.11 записывается в `CLAUDE.md`: старые версии в папке установки **не удаляются**, на GitHub выкладывается **каждая третья версия**.

## Что остаётся строителю

Точные тексты README и оглавления, список файлов «в архив» (по отчёту помощника, который читает все документы), формат вывода скриптов.
