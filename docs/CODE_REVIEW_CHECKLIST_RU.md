# Код-ревью каждого файла: чек-лист

Решение владельца 21.11: проверить **каждый файл кода** плагином ревью и вести список. Шаг плана — 1.13 в `docs/PLAN_RAZRABOTKI_RU.md`.

**Как проверять один файл:**
1. Ревью плагином: `/ponytail:ponytail-review <путь к файлу>` (ищет ошибки, риски, лишний код; кода не меняет). Для крупных или опасных файлов (сохранения, деньги, физика) ещё `/code-review high <путь>`.
2. Найденное записать в строку файла: «чисто» или номера находок; находки уровня «надо чинить» сразу заводить задачей и чинить отдельным коммитом с тестом.
3. Поставить `[x]`, дату и кто проверял. Файл, изменённый после ревью, снова снимается в `[ ]`.

**Порядок:** сначала то, где ошибка дороже всего — сохранения, деньги и износ, физика, ввод, — потом остальное (так стоят и разделы ниже).

Обозначения: `[ ]` не проверен · `[x]` проверен · в скобках число строк на 21.11.
