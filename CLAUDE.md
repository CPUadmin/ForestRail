# CLAUDE.md: правила проекта «Лесная колея» (ForestRail)

Игра для Windows на Godot 4.7.2 (GDScript) про лесную железную дорогу. Над ней работают двое: **владелец** (пишет по-русски, решает) и **Claude** (ведущий разработчик и геймдизайнер). Картинки рисует **GPT** по заданиям. Код хранится на этом компьютере и на GitHub `CPUadmin/ForestRail` (ветка `main`, репозиторий публичный).

## Первое правило владельца (важнее остальных)

- Пользуйся всем, что есть: навыки (`model-router`, superpowers, навыки дизайна), плагины, помощники. Поиск отдавай Haiku, понятные правки Sonnet, сложное Opus.
- **Перед сложной частью предупреди владельца и попроси переключить модель** одной короткой строкой. Если хватит модели попроще, тоже скажи.

## Как говорить с владельцем

- По-русски, просто и коротко (у владельца СДВГ). В отчёте сначала **что видно в игре**, потом **что не проверено**.
- Вопросы по одному, в виде «А / Б / В» с твоим советом. Крупные решения по игре и экономике сначала предлагай, потом делай.
- Не выдавай непроверенное за проверенное. Автотесты не равны пробе человеком, оценка по коду не равна замеру.
- Порядок важности: **ошибки → геймплей → вид → новое**.

## Инструменты

Путь к Godot хранится в `tools/local_settings.json` (не в git, образец: `tools/local_settings.example.json`).

- `python tools/run_all_checks.py`: все наборы тестов **по одному** (~40 мин), итог в `qa/last_run/summary.txt`. `--only a,b` гоняет выбранные, `--skip a,b` пропускает.
- `python tools/visual_audit.py`: кадры всех 9 машин (день, ночь с фонарём, ход, торможение, юз) и депо в `qa/visual_audit_latest/`. **Смотреть глазами крупно.**
- `python tools/build_trial.py`: пробная сборка из последнего коммита в `release/trial/<версия>/` с проверкой готового exe. Без выпуска.
- `python tools/run_checks.py <godot.exe> --manual-run --suite <имя>`: один набор (так зовут скрипты выше).
- `python tools/art_intake.py`: приёмка картинок GPT.
- `python tools/extract_from_main.py`: вынос функций из `main.gd` в помощник (см. его описание).
- Тесты инструментов: `python -m unittest tools/test_devenv.py`.

## Правила работы

- **Тесты никогда не запускать параллельно.** Перед запуском убедись, что нет процессов `Godot*`. `run_all_checks.py` проверяет это сам. Остановка фоновой задачи не убивает её Godot: завершай всю цепочку.
- Имена наборов бери только из `ForestRail/tests/` (несуществующее имя даёт ложный «красный»).
- **Один шаг = один понятный результат = один небольшой коммит.** Коммит только по именам файлов, **никогда `git add -A`**. Сообщение по-русски, последняя строка `Co-Authored-By: Claude <модель> <noreply@anthropic.com>`.
- Не трогать чужие неотслеженные файлы. Не править тесты под неверное поведение.
- Концы строк: везде LF, у `.bat`/`.cmd`/`.ps1` CRLF (`.gitattributes`).
- Перед выпуском обязательны: все наборы зелёные (кроме `check_save_p8`, ему нужно старое сохранение), `check_lifecycle` (оба режима: карьера и творческий), **визуальная проверка глазами**, замер кадра (`check_perf_budget`), сборка из чистой копии без «No loader found» в логах.
- Новая версия обязана читать старые сохранения.
- Числа в интерфейсе берутся из данных, а не пишутся руками.

## Версии и выпуски

- Номер: `ЭПОХА.ВЫПУСК.ШАГ.ПРАВКА`, пробные сборки `-B1`, `-B2`… (например `1.2.1.0-B1`).
- **Выпуск, тег, релиз на GitHub, установка и смена ярлыка делаются только по слову владельца** («выпускай»).
- **Старые версии в папке установки `%LOCALAPPDATA%\Programs\ForestRail` не удалять.**
- **На GitHub выкладывается каждая третья версия** (решение 14.11.2026).

## Картинки и звук

- Сложные картинки рисует **GPT по заданию**, а не код. Claude пишет задание в `briefs/`, ставит строку в `ART_QUEUE.md` со статусом `waiting for GPT`, потом принимает картинки (`art_intake.py`) и подключает.
- На картинках **нет букв и цифр** (надписи ставит игра). Фон `#FF00FF`, свет и дым на `#000000`. Стиль: тёплый, потёртый, сильный объём, латунь и тёмное дерево.
- Картинки игры хранятся **без сжатия с потерями** (решение владельца 14.11.2026).
- Анимации делаются кодом в Godot: пружины, маятники, Tween, шейдеры. От GPT нужны неподвижные детали.
- Каждый внешний звук или шрифт записывается в `docs/AUDIO_CREDITS_RU.md` с автором и лицензией.

## Тон текстов игры

- Тёплый и ироничный, без давления.
- В казике: никогда «не выиграешь», только «вот-вот» и «почти»; нет «ещё раз!», таймеров и приманок после проигрыша; «хватит» доступно всегда; жетоны за деньги не продаются. Реплики свои, без цитат известных людей.
